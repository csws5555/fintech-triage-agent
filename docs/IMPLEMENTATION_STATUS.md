`test_rag_pipeline.py` module for the roadmap's pipeline matrix and
`test_retriever.py` for mandatory policy-filter/no-unfiltered-fallback
assertions. The added edge cases cover malformed Ollama ports, incorrect Nomic
prefix configuration, classifier result cardinality and score validity, real
long-input truncation arguments, and blank document embedding input.

Step 31 adds no application public-interface change. Its operator entry points
are `python scripts/test_retrieval.py` and
`python scripts/test_rag_pipeline.py`. The reusable, fake-testable seams are
`scripts.test_retrieval.run_live_retrieval_checks(...)` and
`scripts.test_rag_pipeline.run_live_pipeline_checks(...)`. Pytest discovery is
restricted to `backend/tests/` so the roadmap-mandated operator script names
are not collected as test modules. The live pipeline command prints the full
safe report on success. When generation is safely rejected by output
validation and every routing, retrieval, invocation, containment, and
configured metadata invariant still matches, it prints
`PIPELINE_SAFE / GENERATION_REJECTED` with `validator=REJECTED:<code>` and
returns exit code 1 for the strict generation-quality check. Only genuine
pipeline invariant failures retain the `FAIL` label. Safe diagnostics include
expected-versus-actual route, response-mode, policy-ID, LLM-call, validator,
retrieval-sufficiency, human-support, and final-customer-answer facts without
exposing prompts, rejected generated text, policy bodies, scores, paths, or
secrets.

Step 32 adds the read-only operator entry point
`python scripts/test_phase2_matrix.py` and the reusable
`scripts.test_phase2_matrix.run_phase2_matrix(...)` seam. The existing
`scripts.test_rag_pipeline.run_live_pipeline_checks(...)` remains compatible
and now accepts an optional probe tuple with stricter metadata, content, and
approved post-LLM fallback expectations. Deterministic routing now recognizes
explicit card-order operation requests and app-access failure during a
security incident.

Step 33 adds no application public-interface change. Its operator entry point
is `python scripts/measure_phase2_quality.py`. Reusable fake-testable seams
include `locked_evaluation_cases(...)`, `evaluate_routing_quality(...)`,
`evaluate_safety_quality(...)`, `measure_performance(...)`,
`evaluate_portfolio_goals(...)`, and `build_quality_report(...)`. The command
prints aggregate JSON only and returns nonzero if measurement fails or a stated
portfolio goal is missed.

Step 34 adds service-free redaction and safe structured-log preparation. It
replaces obvious card, contextual OTP/PIN/CVV, password, bearer-token, and
API-key-like values with `[REDACTED]`; converts exact classifier confidence
values into tenth-wide ranges; and rejects any structured field outside the
roadmap allowlist. It does not emit logs or change pipeline contracts because
request IDs, HTTP logging, and transport integration remain Phase 3
responsibilities.

Step 35 adds no application public-interface change. It verifies the existing
`classify_intent(...)`, `FintechRagPipeline.answer(...)`, synchronous buffered
streaming, and asynchronous buffered streaming interfaces for Phase 3. It also
narrows unlabeled long-number redaction to card-context or Luhn-valid values
and prevents vector-store inspection output from printing the local embedding
model digest.
