## Known compatibility risks

- Installed `chromadb==1.5.9` accepts the explicit cosine configuration and
  reports cosine after reopen. It emits a legacy embedding-function
  configuration deprecation warning even though precomputed embeddings are
  supplied; this does not affect the verified result but should be reviewed
  when dependencies are upgraded.
- Windows directory moves must be treated as staged and rollback-capable, not
  universally atomic.
- The Nomic document and query prefixes must be applied exactly once.
- Current approved policies produce 67 chunks at the configured 700/100
  size/overlap. This is derived output, not a hard-coded manifest value.
- Stable IDs do not depend on `chunk_index`; changing policy content, chunk
  settings, heading behavior, normalization, or the ID algorithm will require
  a future Chroma rebuild.
- The runtime ingestion manifest is stored inside the ignored Chroma directory
  and must be regenerated through the protected staged rebuild when policies,
  chunking, stable IDs, embedding configuration/digest/dimensions, collection
  metric/name, or relevant package versions change.
- The working tree contains extensive uncommitted Phase 2 work. Preserve it and
  do not create a commit without explicit user instruction.
